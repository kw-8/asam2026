# Data Acquisition Agent — Design

Design record for the agent that takes a team member from an intuition to a saved signal dataset.
Built step by step following the AI workflow engineering order. Each step is marked **locked** once agreed.

---

## Step 1 — Objectives, success criteria, constraints (locked)

### Objective
Guide a team member (non-technical) from a general intuition or an existing idea to a constructed signal file that joins to the team's panel, plus a record of what was done and why. The agent **coaches**: it stops after every step and helps the user do the work themselves.

Flow:
1. Make the idea concrete: **A impacts B in C way** (driver → outcome, direction, mechanism, horizon).
2. Search literature and existing factor libraries.
   - **Case 1 — exists**: download it directly.
   - **Case 2 — does not exist**: identify candidate definitions and the data each needs → check the panel (and the shared drive) → profile the data's timing **before** downloading → pull from WRDS/Compustat → construct the signal.
3. Save the signal file (CSV or parquet) with the panel's keys and conventions, and update the factor catalog.

### Vocabulary
- **Signal**: candidate information that looks tied to performance.
- **Factor**: a signal verified to be consistent and predictive (not reactive).
- **Data shape** (tracked separately from status): *firm-level* (a value per company per period — can rank stocks) vs *factor returns* (one return series for a portfolio — comparison only).

### Success criteria
1. Output keyed like the panel: `permno`, `gvkey`, `date` (month-end), monthly frequency.
2. Every value has a `published_date` (exact where available) and `period_end`; how the date was determined is recorded.
3. Compustat ↔ CRSP linked through the CCM link table, valid link types, within link date ranges; match rate to the panel reported.
4. Ticker changes handled by keying on PERMNO; at least one known rename/merger spot-checked.
5. Splits: per-share values adjusted with CRSP adjustment factors, or the signal is shown to be split-invariant.
6. Coverage report vs the allowed universe; ETFs marked not-applicable where relevant, never silently dropped.
7. Sanity checks: distribution, outliers, spot checks on well-known firms.
8. Signal definition recorded: formula, economic intuition, citation, deviations from the source.
9. Reproducible: query and construction script saved in the repo; data saved to the shared drive.

### Constraints
- Runs in Claude or Codex; the prompt is a repo markdown file either can read.
- User enters their own WRDS credentials via the `wrds` Python package; the agent never asks for, sees, or stores them.
- WRDS access is read-only; queries pull only needed columns and dates.
- Data never goes on GitHub; it goes to the shared private drive (local copies in `data/`).
- Out of scope: backtesting, signal testing, editing the existing panel.
- Already defined (no judgement needed): universe = all US-listed stocks and ETFs we are allowed to use; frequency = the panel's (monthly); keys = `permno`/`gvkey`.

## Step 2 — Required information, context, representation (draft)

### 2a. Context layers
Kept separate so the agent never confuses rules, facts, and progress.

| Layer | What | Changes | Where |
|---|---|---|---|
| **Instructions** | Role, coaching mode, stop-after-each-step, safety rules (credentials, no data in git) | Rarely | `agents/data_acquisition/PROMPT.md` |
| **Project facts** | Universe, frequency, keys, benchmark, drive layout | Rarely | `config/project.yaml` |
| **Panel data dictionary** | Every panel column: meaning, units, coverage, null rate, known timing lag | When the panel is rebuilt | `reference/panel_dictionary.md` (generated by a script, metadata only) |
| **Factor catalog** | Every signal/factor: have/have-not, source, status, location | Every new signal | `public_data/factor_catalog.csv` |
| **WRDS reference** | Tables, link rules, split adjustment, ticker history, query patterns | Rarely | `reference/wrds_guide.md` |
| **Timing reference** | Filing deadlines, report-date fields, restatements, after-close rule | Rarely | `reference/timing_guide.md` |
| **Session state** | Current step, decisions, approvals, open questions for one signal | Every step | `signals/<signal_name>/state.yaml` |

Rules:
- Reference files are authoritative over the model's memory. If they conflict or are silent, the agent stops and asks.
- Each step loads only the context it needs (table 2b).
- Session state is written at the end of every step, so the user can stop and resume, and a reviewer can audit.

### 2b. Information needed per step

| Agent step | Needs |
|---|---|
| 1. Concretize hypothesis (A→B via C) | User's intuition; project facts; factor catalog (does something similar exist?) |
| 2. Search literature / libraries | Hypothesis; factor catalog; library list + access methods; web search |
| 3a. Case 1: download | Source access method; output schema |
| 3b. Case 2: candidate definitions + data needs | Panel dictionary; **ask user what is on the shared drive but not local**; WRDS reference |
| 4. Timing profile (before any download) | Timing reference; WRDS reference |
| 5. Pull data (user runs code) | WRDS reference; data plan from state |
| 6. Construct signal | Output schema; ID/split rules |
| 7. Validate | Success criteria checklist; panel (for match rate) |
| 8. Save + catalog update | Drive layout; catalog |

### 2c. Representations

**Hypothesis spec** (in `state.yaml`)
- `driver` (A), `target` (B), `direction` (+/−), `mechanism` (C, why), `horizon`
- `why_predictive_not_reactive`
- `applies_to`: stocks / ETFs / both

**Signal data.** The existing panel is assumed on time. An event file is needed only for late-reported data (fundamentals, 10-Q/10-K, filings); market data (prices, returns, volume) goes straight to the monthly file.
1. **Event file** (late-reported data only; one row per observation as published; on the drive)
   `permno, gvkey, period_end, published_date, date_source (exact|assumed), source, raw input columns…, version (original|restated)`
2. **Monthly panel file** (joins to the panel; on the drive)
   `permno, gvkey, date (month-end), <signal_name>, period_end, published_date, date_source, source`
   Built as-of: for each month-end, the latest event with `published_date <=` that month-end (after-close filings count from the next trading day).

**Factor catalog entry**
`name, category, status (have-idea|have-data|signal|factor|rejected), hypothesis, definition, data_shape, source, citation, inputs_required (+ in panel?), location, frequency, coverage_start, coverage_end, timing_rule, added_by, date_added, test_results`

### 2d. Facts about the current panel (verified 2026-11-11)
- `crsp_monthly_ratios_clean.parquet`: monthly, 1980-01 → 2025-12, keyed `permno` + `date` (month-end), no duplicates.
- CRSP CIZ (v2) column names (`mthcaldt`, `mthret`, `primaryexch`) → **rule: all new CRSP pulls use the CIZ (v2) tables**, never the legacy format, so fields and definitions match.
- Units: `shrout` in thousands; `me` = `prc × shrout` (thousands of dollars).
- `gvkey` missing on 11.5% of rows; accounting ratios ~14–33% missing.
- Accounting ratios change ~2 months after calendar quarter end (checked on AAPL, MSFT) → likely WRDS Financial Ratios Suite lag. Possibly early for slow small-firm 10-K filers; verify per signal.
- ETFs: only a teammate's selection (≈46 fund permnos), not the full allowed universe.
- Requires `pyarrow>=24` to read.
